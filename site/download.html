Lynn CLI / Lynn Code

给开发者和其他智能体的安装方式

Lynn CLI 当前最新为 v0.86.4。它是 Lynn 的终端版:跑在命令行里的 AI 编码助手,带终端 TUI、Markdown 渲染、流式输出、工具调用和长任务续跑。 一行命令装好,不用克隆仓库、不用编译;也可以被 Claude Code、Codex CLI、Kimi Code、Qwen CLI、CI 或 Lynn GUI Fleet 以无交互方式调用。

Node.js 20 LTS 或 22 LTS

1. 先准备 Node 环境

如果机器已经有 Node 20+ 和 npm，可以直接跳到下一步。先用 node -v 确认版本不低于 v20。

node -v

# macOS(Homebrew)
brew install node@20

# macOS / Linux(nvm)
nvm install 20 && nvm use 20

# Windows
winget install OpenJS.NodeJS.LTS
首次安装 / 覆盖升级

2. 安装 Lynn CLI

第一次安装和覆盖旧版本都用这条命令。--force 首次安装也无害,并能覆盖旧的 lynn/Lynn 命令软链接,避免 npm 提示 EEXIST。包走腾讯云镜像,国内直连快。

npm install -g --force https://download.merkyorlynn.com/downloads/cli/lynn-cli-0.86.4.tgz
启动命令

3. 启动 Lynn

默认走 Brain V2 路由:本地 Lynn Brain 可用时优先本地,不可用时自动回到远端 Brain。编码任务默认使用 auto harness:协议与当前认证/provider/model 的真实预检通过才进入 Codex app-server,否则在启动前使用 Lynn 原 Loop；ask/workspace-write 保留审批，多模态、JSON 逐工具审计、Ultra 和 never deny-all 继续走原架构。实验性 manager 仍可通过 Lynn manager run -p ... --jsonl 显式调用。

Lynn                 # 交互式聊天 TUI
Lynn code            # 编码 agent TUI
Lynn manager run -p "拆分并验收这个长任务" --jsonl
Lynn --version       # 应输出 0.86.4
Lynn agents          # 输出可复制的 Fleet / 其他 CLI 调用方式

# 无交互编码 worker 示例
Lynn code -p "fix tests, run the suite, summarize the diff" \
  --json \
  --cwd /path/to/worktree \
  --approval yolo \
  --sandbox danger-full-access \
  --save-session

安装前你可能想知道

我怎么知道我的 Mac 是 Apple Silicon 还是 Intel？

点击左上角苹果菜单，选择“关于本机”。如果看到 M 系列芯片，就是 Apple Silicon；如果看到 Intel，就是 Intel 版。

Windows 弹出安全提示还能装吗？

可以。正式发布安装包会完成 Windows 代码签名；SmartScreen 仍可能因为新版应用声誉积累不足而提示确认。

我想看更新说明或校验原始发布记录怎么办？

你可以直接打开 Gitee Release 页面查看所有历史版本、更新说明和备用下载入口。

V0.86.4：自动任务 UI 与渲染按需加载

V0.86.4 修复自动任务在暗色主题下的大面积浅色背景、低对比度文字和不可读控件，并把数据、草稿、模板库与编辑器拆成独立模块。Mermaid、Wardley、KaTeX、Markdown 和 sanitize vendor 改为真正按需加载，同时加入多主题、多分辨率截图回归门禁。 v0.86.3 建立的 Codex harness 自动预检、原 Loop 回退与跨端终态契约保持不变；Windows 安装包继续内置 llama.cpp 运行时。

  • 自动任务模板、任务卡、表单、状态标签与操作按钮在亮色和暗色主题下均可读
  • AutomationPanel 拆为数据 Hook、草稿 Hook、模板库和编辑器模块
  • Automation 专属样式从通用 Floating Panels 样式表迁出
  • Mermaid、Wardley、KaTeX、Markdown 与 sanitize vendor 真正按需加载
  • 静态依赖门禁防止重型渲染器重新进入主 bundle
  • 亮色/暗色 × 三种视口共六组截图基线进入发布 UI 门禁
  • Codex app-server 自动预检、原 Loop 回退与 GUI/CLI 终态契约保持不变
  • Windows 继续内置 llama-server.exe、依赖 DLL、许可证和逐文件 SHA-256 清单
  • macOS/Windows 打包统一经过 Agent regression、CLI100、GUI100、全部 UI 与真实安装门禁
